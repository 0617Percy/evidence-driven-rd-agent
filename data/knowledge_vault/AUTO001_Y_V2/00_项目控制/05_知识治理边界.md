# 05_知识治理边界｜统一知识治理边界（长期规则）

> 定位：本项目长期有效的统一知识治理边界。后续整理、检索、知识更新、RAG 准备时均需遵守。
>
> 生效：2026-08-30 记录并生效。本次只记录规则，不修改、移动、重命名任何现有文件。

## 一、可以作为企业事实真源 / 正式知识依据的内容

### 1. `01_原始资料`

- 企业提供的原始脱敏模拟数据；
- 默认只读；
- 属于事实真源。

### 2. Y 侧已经人工确认并 Freeze 的正式业务知识

包括但不限于：

- Scene；
- MVP Freeze；
- EvidenceMap；
- GoldSources；
- GoldAnswer；
- Prompt Contract；
- EvidenceGap；
- EvalSet 的定义部分；
- 正式 Gate / Freeze 裁决。

这些文件可以作为业务规则和验收依据。

## 二、默认不得直接进入 RAG / Gold / 正式 Evidence / Master KB 的内容

### 1. `03_评测` 下的内容

- Runtime 输出；
- Eval JSON/TXT；
- Regression 结果；
- Safety 结果；
- Contract 测试结果；
- Smoke Test 结果。

**用途：评测、审计、验证。不是企业事实真源。**

### 2. `90_开发协作` 下的内容

- W→Y / Y→W 交接文件；
- 技术说明；
- Gate 汇报。

**用途：协作与审计。**

除非其中某项已被 Y 明确裁决并同步进正式 Freeze 文件，否则不要直接作为 RAG 知识。

### 3. `outputs` / 运行产物

包括：

- LLM 生成回答；
- Structured Output；
- Retriever 结果；
- Validator 结果；
- Qdrant 索引；
- 日志；
- 临时 JSON/TXT。

**这些均不是事实真源。**

### 4. Frozen Demo 样例

**用途：路演稳定展示和回归测试。不是新的企业 Evidence。**

### 5. Knowledge Evolution / Knowledge Curator 产物

尤其：`kb_update_candidates.jsonl`

其状态只能理解为：

- PENDING_REVIEW；
- NOT_APPROVED_EVIDENCE；
- approved_for_master_kb = false；
- master_kb_write_allowed = false。

禁止：

- 直接进入 RAG；
- 直接进入 Gold；
- 直接作为 Evidence；
- 自动写入 Master KB；
- 自动 re-index。

只有在 Y / 研发工程师人工审核，并补充可追溯正式 Evidence 后，才能进入 Master KB 及后续 Runtime Snapshot。

`query_traces.jsonl` 仅用于知识治理审计和追踪，同样不进入 RAG。

## 三、特别禁止

不得把以下内容因为"看起来合理"就升级为正式知识：

- 用户问题；
- LLM 回答；
- LLM 推断；
- Recommended Validation；
- Knowledge Curator 建议；
- Eval 测试输出；
- Runtime 结果；
- Demo 样例；
- 未经人工批准的 Candidate。

### 冻结原则

```text
USER_QUESTION_IS_EVIDENCE = NO
LLM_ANSWER_IS_APPROVED_EVIDENCE = NO
AUTO_WRITE_MASTER_KB = NO
AUTO_APPROVE_KNOWLEDGE = NO
AUTO_REINDEX = NO
HUMAN_REVIEW_REQUIRED = YES
```

## 四、无法判断时的默认处理

如果未来无法判断某个文件能不能进入 RAG：

- 默认：**"不进入"**；
- 先标记为：**待 Y 人工确认**；
- 不要自行推断或自动升级。
