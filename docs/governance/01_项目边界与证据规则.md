# 项目边界与证据规则

## 当前产品边界
做：
- 历史研发经验检索
- 失败案例优先召回
- 成功/规则对照
- 风险提示
- 下一步“优先验证什么”
- 证据引用
- 不确定性说明

不做：
- AI 直接拍板最终配方
- 无证据的精确参数推荐
- 自动替代研发工程师
- 为了 Demo 编造企业事实

## 证据等级

### E1｜直接数据/原始记录
CSV、实验记录、性能测试、8D 原文、项目报告原文。

### E2｜正式规则/标准
工艺通则、行业标准、企业正式技术资料。

### E3｜人工确认的结构化知识
从 E1/E2 抽取，经人工复核的知识对象。

### E4｜AI 推断
基于 E1–E3 的综合判断。必须明确标注为“AI推断/建议”，不能伪装成事实。

## 回答底线
- 关键数字必须能定位到源数据。
- 关键风险必须有来源。
- 来源冲突时展示冲突，不擅自合并成确定结论。
- 证据不足时输出“不足以判断”，而不是补全。
